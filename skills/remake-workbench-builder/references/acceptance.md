# 验收

1. 源提示词逐字保留；展开每页提示词与已审阅脚本离线输出一致；预置图片哈希一致。
2. 非法分页、带图玩法缺失角色、未实现步骤、依赖或系统消息不能继续生成。循环顺序、封面/总结、显示文字与结构一致。
3. 确认前零图片调用；发布文案不当作上图文字；带图玩法实际携带指定角色图；纯文字玩法图片输入为0，不能继承上一玩法的图片。
4. 模型JSON不合规至多重试2次；接口失败不自动重试。失败保留已完成文字和图片，单页重画保留旧版。重复点击不启动重复任务。
5. 关闭重开保留历史；中断状态可恢复。不同玩法与版本隔离，不能覆盖已有任务使用的源。
6. 页面没有单任务提示词输入；模型设置不回显密钥；导出不含密钥；本机服务检查来源和写操作令牌。
7. 桌面浏览器实测：打开、选择、输入、确认、失败状态、历史、放大、复制、下载；窄屏不溢出。模拟模型和实际供应商分开说明。
8. 交付真实边界：当前操作系统、其他系统是否实机测试；Skill 是否安装；哪些模型已实测；历史图片来自何处。

测试方法：`python3 -m unittest discover -s tests -v`。真实模型费用、事实核验与视觉验收不能由模拟接口替代。涉及实时或专业主题时，当前知识卡文字步骤没有联网；不要声称工作台具备事实核查，后续需要单独实现来源输入或核验步骤。

设计验收：读取 DESIGN.md，对照所附真实截图和底座CSS检查布局、字体、色彩、间距、状态与响应式。新增工作台必须随附DESIGN.md及assets/design-reference.jpg；没有用户新要求时保持当前视觉基线。

模型连接引导验收：首次缺少连接时是否明确询问Base URL、模型名称和API Key，是否提供本机密钥填写方式；已有值是否复用、仅追问缺项；用户暂不提供时是否记录待配置并继续独立工作；不能以创建设置页面代替询问。密钥不得写进Skill、截图、示例、报告或公开交付包。

四板块与新增验收：首页只展示本次任务；玩法库详情有流程、只读完整提示词和独立样张；历史不含样张。首次创建后追加第二玩法，两者都能运行，重复登记无重复条目。workbench.json引用必须有效，并纳入版本哈希。新目录安装测试不得依赖开发者工作区绝对路径、模型密钥或原测试素材目录。
