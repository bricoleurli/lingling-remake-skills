# 爆款复刻机 · Codex版

将一套有顺序的参考图文，拆成可更换内容的生成流程。用户在对话里提供资料和反馈；Agent负责分析、执行、维护可视化入口，最后交付可搬运文件包。

## 安装与第一次使用

解压技能包，将完整的 `flow-spec-builder` 文件夹放到自己的 `~/.codex/skills/` 下。已有同名技能时先保留旧版本，不合并不同版本文件。也可以把压缩包交给Codex，明确说“安装这个技能”。

在新对话中输入：

> 使用 $flow-spec-builder，按照图片上传顺序分析这一套参考图文，按技能步骤与我确认并完成流程交付。

同时附上有顺序的图片。标题、正文、标签可一起提供，也可以等Agent问到时选择稍后补。第一次不用准备账号资料或回答抽象的用途问题；角色、以后输入什么和页数会在分析/还原之后讨论。

需要：能读图片和本地文件的Agent、Python 3.10及以上。技能新增工具仅依赖Python标准库。实际生图需要所在环境提供生图工具，或用户选择配置外部API；没有工具时交付标注未生成的方案，不能假装已完成测试。使用其他模型时图片效果可能不同，页面结构和流程契约可以复用。

## 用户会经历什么

1. 上传图片，决定是否补发布文案。
2. 查看参考规律和逐页分析。
3. 查看全套还原方案；确认后纯文字生成，再看原图对照并反馈。
4. 确认以后输入、页数、内容来源与角色方式。
5. Agent编写完整流程。
6. 查看并确认完整提示词、槽位、模型、调用次数和输入输出。
7. 按需做新主题测试并反馈；也可明确跳过。
8. 获得完整文件包，交给其他工具继续做应用。

用户只需记住一个index.html入口；阶段内容分别保留版本。页面有侧边抽屉、标签页、完整提示词复制、槽位高亮。用户在聊天里回答，页面不会偷偷运行模型或提交决定。

## 最终拿到什么

- flow.html：完整流程和提示词的可视化入口。
- flow.json：给程序或后续工具读取的完整结构化源。
- spec.md：同源生成的文字规格。
- 必需的参考图、角色预设、脚本、真实测试结果和执行记录。
- FILES.md、files.json：实际文件数量和清单；ZIP用于整体搬运。

文件数随图片数量、测试轮次和修改版本变化。一个HTML是阅读入口，不意味着物理上只有一个文件。技能包不携带当前用户的案例、角色和生成结果。

## Agent执行入口

先读SKILL.md，再读references/user-journey.md和references/case-operations.md。使用scripts/casebook.py管理案例，而不是重新编写同类脚本。

```bash
python3 scripts/casebook.py --help
python3 evals/test_casebook.py
```

测试使用合成夹具，验证文件工作流和拒绝遗漏的行为；它不调用模型，不替代真实图像质量或新会话对话测试。版本与证据边界见references/codex-maintenance.md及reports/verification.md。

## 更新和恢复

个人安装以当前技能目录为准。升级时先备份旧技能，完整替换技能文件夹；案例文件留在工作区，不随技能更新移动。需要回退时恢复旧技能文件夹；case.json含创建时技能版本，阶段和最终交付均保留历史。
