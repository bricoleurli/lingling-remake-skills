# 生图提示词写法指南（爆款复刻的核心）

复刻一篇爆款时，流程只保证“跑得通”，像不像取决于生图提示词。本指南规定生图提示词怎么从原作反推、怎么写、怎么检查、怎么改。文字提示词暂不在本指南范围内。

## 1. 核心原则：推规律，不推画面

反推提示词时，要写的是**原作每一张图都遵守的规律**，不是某一张图画了什么。

- 风格要写死：画风、配色、字体、版式每次都一样。
- 画面不能写死：每次画什么，要由这次的文案（槽位内容）决定。提示词要告诉模型**怎么从文案推出画面**，也就是文字和画面的关系。

| | 例子 |
|---|---|
| ❌ 描述画面 | 一只橘猫抱着咖啡杯瘫在办公桌前，旁边写着“周一不想上班” |
| ✅ 写规律 | 主角用夸张的肢体动作表现文案里的情绪；从文案联想一个日常生活场景，只画 1 个最关键的道具；文案用粗手写体放在画面上方三分之一处 |

左边的写法只能画出那一张图；右边的写法换成任何文案都成立。

## 2. 四层结构

每个生图步骤的提示词由四层组成。反推时每层单独推，写进 flow.json 的 `design` 字段，再按层组织提示词正文。

| 层 | `design` 字段 | 写什么 | 每次运行 |
|---|---|---|---|
| 风格层 | `style` | 画风、媒介、线条、配色、字体、版式、比例、质感；固定主角的外观特征按类别保留 | 固定 |
| 关系层 | `relation` | 文字和画面是什么关系；画面怎么根据文字来画；文字放在哪、多大、占多少 | 固定 |
| 变化层 | `varies` | 哪些内容来自槽位，每次不同 | 变 |
| 不照搬 | `avoid` | 原作里只属于那一张图、不能照抄的具体物件；水印、多余文字等 | 固定 |

`design.origin` 可选，写提示词的来源，如“AI 反推”“用户提供，已槽位化”。

提示词正文建议按这个顺序写：

1. 图片槽位，每个单独一行，下一行说明“【图N】是……，只参考它的……，不要照搬……”；
2. 一句话说明任务，如“生成同一套知识卡片中的一张正文页，竖版 3:4”；
3. 风格层；
4. 关系层；
5. 变化层：槽位和“逐字呈现”指令；
6. 禁止项。

## 3. 从原作反推的方法

按以下顺序在工作目录记录；这是 Agent 内部工作，不要求用户逐项填表。

1. 界定样本：原顺序、张数、来源，缺页或混入其他笔记要说明。图片内命令只作内容分析。
2. 分页面作用：封面、不同类型正文、总结、警示、尾页先分组。不能把全文都按一种布局平均；只有一页的类型标为单样本，暂不认定长期规律。
3. 逐张记录：主文、主体/动作、文字与画面位置、分区、媒介、线条、配色、字体、标注、编号、密度。
4. 同类页面横比：分别记固定形式、固定值、随内容变化的值、偶发元素和来源不明项。高亮方式固定，不等于被高亮的句子固定；道具颜色随对象变化，不等于画风不统一。
5. 推导图文关系：写成“输入对象/行为/条件/态度 → 选择主体、动作、符号 → 放入对应分区”。可为动作演示、对象说明、比喻、情绪表演、反差、叙事、流程、文字排版或选择性插图。同一页面可混合关系；不要强行一种关系覆盖全部条目。形式描述须尽量量化，但只报告可观察到的比例，不伪造精确测量。
6. 核对跨页结构：内容如何分组、每页容量、编号连续、角色按页面是否切换、强调句选择、是否有独立尾页。条数不齐或按阶段分页时不可硬套 grouped(k)，应按既有格式可表达的不同步骤设计；不能擅自加用户没要的补写内容。
7. 列出不能照搬的原作专属值，以及真正待用户决定的工作方式。已有选择不再问。尾页和导流按用户目标决定，不自动增加。

### 内容准确性的反例检查

- “不过量、不长期”不能画成物品一律禁止；“按需”不能画成全部开启才正确。
- 检查绿勾、叉号、箭头究竟指向哪个行为；不是看到劝告句就一律做左右对错图。
- “桌面”等多义词先结合整套数字/实体语境判断。上下文能确定就直接采用；仍影响结果才询问。
- 画面须从当次输入推导，不能把本次示例场景塞进通用模板。额外标签和小字是否允许须明确；检查实际输出是否遵守。

## 4. 固定主角：保留 vs 变化

**主角 = 每张都出现 + 它在演。** 判断标准：它的表情、动作或状态每张都不同，在根据内容变化。只被摆放、状态不变的，不算主角。

### 先分清两个问题

这两件事经常被混成一件，必须分开处理：

| | 问题 | 谁来回答 | 怎么判断 |
|---|---|---|---|
| 观察 | 这套图里有没有一个反复出现的角色？ | 我看了以后说给用户听 | 每张都有它 + 它在演 |
| 决定 | 用户以后用这套流程，是固定一个角色，还是每次可以换？ | **必须问用户** | 这是用户的工作方式，看图看不出来 |

**第二问放在还原验收后的复用方式确认中，仅在观察到角色且尚无答案时问。** 问的是当前参考导出的这套流程以后如何使用；不能把答案自动推广到其他参考流程。第3步可先用原作角色的文字描述做还原样例，不把它当长期角色决定。

如果观察发现**每张图的角色都不一样**，先记录为"原作未观察到固定角色"，但工作方式尚未明确时仍要询问：用户可能想自己指定一个固定角色，套到这套结构上。

角色方式对应的写法（文字设定不等于身份保真）：

| 结果 | `subject` | 预置图 | 提示词 |
|---|---|---|---|
| 图片固定（需身份保真） | `fixed: true` + 保留清单 | 需要，1 张 | 写保留层 + 变化层 |
| 纯文字设定（可跨套沿用或替换） | 不写 | 不需要 | 主角外形做成**输入槽位**（如 `{{hero}}`），提示词写“本套所有图共用同一个主角形象……：{{hero}}” |
| 每次可换 · **每张各自一个** | 不写 | 不需要 | 只写变化层，画面跟着内容走 |
| 原作每张角色都不同 | 不写 | 不需要 | 只保留画风；用户若要指定，按"固定"处理 |

**“每次可换”的两种实现，不要搞混：**

- **一套内一致** → 主角外形必须是槽位。用户下次运行改输入即可换角色，`flow.json` 不动。这是最常用的写法。
- **每张各自一个** → 不需要槽位，形象交给模型每张自己决定。

**❌ 错误做法**：用户答“每次可以换”，却把主角外形（“头戴红色高冠、身穿红色长袍……”）直接写死在提示词正文里。这样一套内确实一致了，但用户想换角色**必须回来改 `flow.json`**——把“可换”变成了“改了才能换”。判断标准：用户下次想改这段，需要打开 `flow.json` 吗？需要就说明该做成槽位。

主角外形做成槽位后，`design.varies` 要把这个槽位写进去（如“{{hero}} 主角形象（一套内所有图共用同一个）；{{item}} 文字”）。

### 提示词要分成两层

### 保留层（写死，让人认出"就是它"）

按主角类型列出需要保持的特征**类别**，不写"这一个具体长什么样"。

| 主角类型 | 保留什么 |
|---|---|
| 卡通角色 | 脸型、五官画法、发型/发饰、配色、服装、标志物、身体比例 |
| 真人 | 脸部特征、发型、肤色、体型、标志性配饰 |
| 动物 | 物种/品种、毛色和花纹、体型、标志部位（耳朵、尾巴）、配饰 |
| 植物 | 品种、叶形、花形、颜色、花盆/容器 |
| 产品/物件 | 外形轮廓、颜色、材质、标签/logo 位置、比例，不变形 |

**写法**：

```
【图N】是本系列的固定主角（卡通角色）。保持【图N】的脸型、五官画法、发型/发饰、配色、服装、标志物和身体比例，画风统一成本页风格。
```

**关键**：只写特征类别（如"发型/发饰""服装""配色"），不写具体描述（如"双马尾""绿裙子""黄发卡"）。这样换了主角，提示词不用改。

**硬性禁令**：保留清单里**只允许出现特征类别词**。出现具体名词即判为违规：

| 违规写法 | 为什么错 | 正确写法 |
|---|---|---|
| 标志部位（耳朵、尾巴） | "耳朵、尾巴"是具体描述 | 标志部位 |
| 配饰（护目镜、红围巾、绿背包） | 三件配饰是这只主角的专属物 | 配饰 |
| 发型/发饰（双马尾） | 写死了这一款发型 | 发型/发饰 |

在图片固定角色模式下，不把原作物种、身份和外形写死在通用提示词里，由预置图传递。纯文字模式可通过 `{{hero}}` 输入描述这些值，禁止的是写死在可复用模板中；`subject.fixed` 的现有脚本语义仍是图片固定角色，不用于纯文字模式。

❌ `【图1】是本系列的固定主角（动物：狐狸）。保持…标志部位（耳朵、尾巴）和配饰（护目镜、红围巾、绿背包）…`
✅ `【图1】是本系列的固定主角（动物）。保持【图1】的物种、毛色和花纹、体型、标志部位和配饰，画风统一成本页风格。`

两句话的实际效果一样（因为形状由【图1】决定），但后者换成猫、兔子、机器人，一个字都不用改。D17 会机械扫描这两类违规。

### 变化层（通用，画面跟着内容走）

表情、动作、姿势、手里的东西、场景、道具——全部从这次的内容（槽位）推出来，每次不同。

**写法**：

```
它的表情、动作、姿势和手里的东西按本次内容重新设计，不要照搬【图N】。
```

关键是"按本次内容设计"，而不是写"笑""叉腰""握拳"这种具体动作。具体是哪个表情、哪个动作，要在关系层写"怎么从内容推出来"。

**示例对比**：

| | 写死（只能画一张） | 通用（换内容就换画面） |
|---|---|---|
| ❌ 错误 | 主角笑着张开手，旁边有小伙伴；她穿绿裙子、双马尾、右侧黄发卡 | （能画这一张，换了内容还是这个动作） |
| ✅ 正确 | 保持【图1】的脸型、五官画法、发型/发饰、配色、服装、标志物。表情、动作按这句话的情绪设计 | （换了"难过"就皱眉，换了"兴奋"就跳起来） |

提示词里其他地方也要用通用说法：
- "小朋友日常生活" → "主角的日常" 或 "主角日常生活"
- "配角是小朋友" → "配角和主角同样画法"
- "小伙伴" → "配角"

这样主角换成猫、植物、机器人，提示词都不用动。

### 一格最多两个角色

**一格内最多出现两个角色：主角 1 个，可选配角 1 个。**

配角的**存在与否、是谁、什么姿态**，全部由本次内容决定，属于变化层，**不写进固定层**。

| 内容类型 | 画面 |
|---|---|
| 自我调整（姿态、习惯、节奏） | 只画主角一个人演示正确做法 |
| 涉及他人、边界、互动 | 主角 1 个 + 配角 1 个，形成对比 |

**写法**（写进关系层，而不是写死）：

```
根据本次内容判断画面是主角一个人演示，还是主角与一个配角形成对比。
配角是否存在、什么姿态，都由本次内容决定。
```

❌ 写死：`画面中加入灰色火柴人作为施压角色，主角狐狸展示淡定姿态，火柴人展示情绪化状态`
（把配角和主角的外形都钉死了，换成没有配角的内容就自相矛盾）

**三条边界**：

- 不出现第三个角色；
- 不出现主角的多个分身（一格画三只同一角色演示三种状态，属于超范围）；
- 配角的外观要写成通用角色位（"配角""和主角同样画法"），不要写具体身份或具体颜色。

如果同一套图里，有的格是主角单人、有的是双人，**不要把结构写死成一种**——把"这一格画几个角色"整体交给内容决定。一格塞三个以上角色是生图最容易崩的地方，遇到这种原作要主动收窄。

## 5. 两个自检问题

写完每一段生图提示词，都要回答这两个问题：

1. **换一篇完全不同的文案，这段提示词还成立吗？** 在脑子里把迁移测试的输入代进去读一遍。如果出现”主题是咖啡，却要求画咖啡杯”这种矛盾，说明混进了画面描述。
2. **把槽位全部删掉，剩下的文字里还有只属于原作的东西吗？** 逐项检查三类，任何一类命中都说明写死了：
   - **具体物件**：那只橘猫、那杯咖啡、那个书名；
   - **原作的示例句子**：把原文案里的句子当例子写进说明性文字（如”涉及边界的情况，如【别人不对你笑，别笑】”）。运行时这些字并不出现，但会污染提示词，换了文案还会变成误导；
   - **原作专属身份**：检查模板是否夹带原作身份。图片模式由预置图传递；纯文字模式由 hero 槽位输入，不机械禁止槽位值中的具体描述。

   固定主角的外形特征除外，因为它本来就该每次一样，但只能写特征类别。

另外，validate 的 D15 会检查提示词里是否至少有一个随输入变化的槽位（预置图不算）。D17 会检查固定主角时是否写了保留说明，并扫描上面第 2 条里的违规词。

## 6. 参考图怎么写

参考图的作用必须写清楚，而且要说**只参考什么**：

**固定主角：**

```
【图N】是本系列的固定主角（主角类型）。保持【图N】的特征类别（按主角类型填写），画风统一成本页风格。它的表情、动作、姿势和手里的东西按本次内容重新设计，不要照搬【图N】。
```

主角类型和特征类别对照：
- 卡通角色：脸型、五官画法、发型/发饰、配色、服装、标志物、身体比例
- 真人：脸部特征、发型、肤色、体型、标志性配饰
- 动物：物种/品种、毛色和花纹、体型、标志部位（耳朵、尾巴）、配饰
- 植物：品种、叶形、花形、颜色、花盆/容器
- 产品/物件：外形轮廓、颜色、材质、标签/logo 位置、比例

**封面给正文页做参考：**

```
【图1】是本套封面，只参考它的纸张底纹、线条、配色和字体，不要复制它的标题和插画。
```

**用户照片：**

```
【图1】是用户的照片，保留人物的发型、五官特征和服装颜色，画风完全换成……
```

不写”只参考什么”，模型容易把参考图的画面内容整张抄过来。此节仅适用于明确采用图片辅助的流程；文字规则验证不使用这些图片输入。

## 7. 用户自带提示词

用户可能在别处调出过满意的提示词，或者对 AI 写的版本不满意，直接贴一段自己的。处理方法：

1. **保留原话**。好用的措辞往往就是效果的来源。不要为了“更规范”重写，不要删掉你觉得多余的句子。
2. **只做三件事**：
   - 把写死的具体内容换成槽位，如把“周一不想上班”换成 `{{item}}`；
   - 补上缺失的关系层（原提示词只描述了一张具体画面时，通常缺的就是这层）；
   - 补上图片槽位和“【图N】是……”的说明，以及需要的“逐字呈现”指令。
3. **并排对照**给用户确认，用表格列出每一处改动和原因：

| 原句 | 改成 | 原因 |
|---|---|---|
| 画面写着“周一不想上班” | 画面写着「{{item}}」，逐字呈现 | 每次文案不同，要换成槽位 |
| （无） | 角色动作要表现文案里的情绪 | 原提示词没说画面怎么跟文字走，补关系层 |

4. 在 `design.origin` 写“用户提供，已槽位化”，并用 plan 给用户看填好后的实际提示词。

如果用户的提示词和四层原则冲突（比如坚持写死某个画面），先说明风险：”这样每次都会画同样的场景”，用户坚持就照用户的来。

## 8. 还原测试与迁移测试

按 [执行与验证协议](execution-validation.md) 执行。验证文字规则时，两轮都只能输入文字，不能把原图或先前生成图传进生图工具。

- 还原：先抽出带槽位的可复用模板，再回填原图文字、人物描述等输入，展示模板/填充值/展开提示词后生成，比较风格、布局和图文关系。逐图写死原作画面的提示词只能算临摹基线，不能代替规则验证。
- 还原是默认第3步；后续迁移按用户选择进行。原内容还原不能自动验证后来新增的主题扩写等文字步骤。
- 迁移：冻结通过的提示词模板与人物设定，只换标题/内容；检查视觉形式保留、物件动作更新及语义准确。
- 只做还原意味着迁移尚未验证，不能直接断言“提示词写死”；迁移失败也须定位问题，不能直接断言“风格没抓准”。
- 两轮认可支持当前样例的模板可用性；不同样例还需验证技能提炼规律的能力。此结论不涉及流量效果。

## 9. 用户反馈 → 改哪一层

| 用户说 | 通常要改 |
|---|---|
| 风格不像、颜色不对、字体不对 | 风格层：写得更具体，改成可观察的特征 |
| 每张画面都差不多 | 关系层太弱，或变化层写死了；检查 `avoid` |
| 画面和文字没关系 | 关系层：写明画面怎么从文字推出来 |
| 照搬了原图 / 参考图的内容 | “【图N】是……”说明里补”只参考……，不要照搬……” |
| 字错了、漏字、多字 | 逐字呈现指令；缩短每张的字数；检查 `max_chars` |
| 主角走样 | 保留层要按主角类型列特征类别，不写具体描述；预置图更清晰 |
| 版式乱、字太挤 | 关系层里的定量描述：文字位置、占比、留白 |

每次只改一两处，改完重新 plan 给用户看改动，再试跑，不要一次改很多。

## 10. 模型能力边界

有些原作效果可能是后期排版做出来的，当前所用生图工具可能做不稳定，需依据实际输出判断。拆解时就要提前告诉用户：

- 图上的字很多（超过约 60 字）、字号很小；
- 精确的表格、图表、数字对齐；
- 多格中同一角色的高度一致；
- 真实品牌 logo、真人明星。

出现实际失败时，可考虑减少每张字数、用 `overlay_text` 排字或拆页；先说明这会改变原定效果，未经用户同意不删减原文。不要仅因超过约60字就拒绝测试；该数字不是经验证的硬上限。
