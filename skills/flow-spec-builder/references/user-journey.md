# 用户可见的八步流程

本文件统一规定顺序、展示内容和停顿；执行细节见 [workflow.md](workflow.md)。本技能交付可搬运的复刻流程，不承担网站或应用实现。

## 首次输入

必需：一套按顺序排列的参考图片。顺序明确就沿用，不一律认定第一张必然是封面。

标题、正文、标签仍然可选。收到图片后，若既未提供这些文案、也未说明是否暂不提供，必须明确询问一次，而不是省略这个问题：

> 已收到这组参考图片。要一起补充原笔记的标题、正文和标签吗？可以现在发给我，也可以先只分析图片，后面再补充。

可给“现在补充”“先分析图片，稍后再补”两个选择。已给部分文案时只问缺失项；用户此前已表示暂不提供或先分析图片，直接沿用，不重复索取。提问后可继续清点图片等独立工作，不能把沉默记为拒绝。用户选择先分析图片后照常推进，后补文案时新增相关分析版本，说明是否影响既有模板或需复核，不覆盖旧阶段。不要求用户回答用途，不收账号资料，不在看图前索要角色资产。

## 阶段与用户看到的内容

| 阶段 | Agent 做什么 | 用户看到什么 | 停顿与继续 |
| --- | --- | --- | --- |
| 1 接收参考资料 | 清点图片顺序和可选文案 | 收到哪些资料、接下来会做什么 | 明确问一次是否补可选文案（已有答案则省略）；缺图和顺序有歧义才另问；用户可选择后补 |
| 2 分析参考图文 | 按页型拆风格、布局、文字、图文关系；识别固定项与变量 | 独立分析HTML、简短拆解及例子、不确定项 | 可直接准备第3步方案，用户可纠正观察 |
| 3 原内容回填还原与对照 | 写可复用模板，原内容填槽位；确认后纯文字生成、并排对照 | 生图前：完整模板、槽位值、实际提示词、张数/调用数/图片输入0；生图后：原图对照、偏差、验证结论 | 新方案默认先确认再生成；同一方案不逐张问。生成后等待效果验收。用户明确只要分析、跳过或自动执行时遵循其要求 |
| 4 确认复用方式 | 给出适合这一套流程的输入和分页建议 | 以后输入主题还是成稿、模型补什么、固定什么、页数规则、封面尾页和发布文案范围；有角色时再确认角色方式 | 停下确认会影响最终方案的选择；已答过的不再问。这些选择针对当前流程，不是所有未来任务的统一偏好 |
| 5 编写完整复刻流程 | 补全部模型/脚本步骤和连接，保留已认可视觉模板 | 进度与关键决定；完整提示词进入交付文件 | 无新歧义可直接完成第6步供审阅 |
| 6 展示完整流程说明 | 提供可展开的 flow.html 和完整规格 | 全局流程、输入输出、页数与调用公式、具体模型或未绑定状态、每步全文提示词、槽位、脚本说明、已实现/待实现/实测状态 | 请用户确认新增的完整流程，决定是否补测试；已有明确授权直接继续 |
| 7 按需补充测试 | 验证新输入生成链路或冻结模板换主题迁移 | 测试目的、内容/张数/调用数、展开提示词、实际结果和已知问题 | 新测试先展示具体方案；认可还原不自动授权迁移。无需重复做第3步已认可且模板未变的还原 |
| 8 定稿交付 | 整理3个核心文件及必要附件 | 一个主入口、完整文件清单、验证覆盖、下游接手方式 | 未做迁移也可交付，写明未验证；不声称普遍稳定 |

## 第3步的默认范围

默认还原用户提供的全部参考图片，保持原顺序，一张参考对应一张还原结果。收到8张就准备8张的完整方案，不自行改成“首轮挑3张代表页”。先区分模板页型不意味着只生成每类一张。

生图前展示全套覆盖表：原图序号、页型、模板、对应槽位值、计划结果与执行状态。若用户明确选择抽样/部分页，记录所选序号、未覆盖页及验收边界；不能把代表页通过说成全套通过。普通“试一轮”“用技能分析”不等于同意缩小范围。

因文字不清、尾页含截图、素材缺失或执行器数量限制等问题不能原样完成时，指出受影响的具体页及可行处理方式；继续准备其余已授权部分，不静默删页，不直接把缩减版设成默认方案。单批数量上限可通过分批执行处理，不是减少总页数的理由。测试范围确认与生图方案确认合并说明，无需增加机械审批。

## 第3步究竟检验什么

**抽出的可复用模板 + 原图提取的内容 → 展开后的提示词 → 纯文字生图 → 原图对照。**

模板表达画风、构图规则、不同页型和“文字如何决定画面”；原句、具体对象和人物外形放槽位。单张页型可以独立模板，但不能每张重新写死原图专属动作、物件和坐标，靠逐图临摹描述证明抽象规律成立。

实际发送的提示词会包含具体画面，这是模板填槽位和按规则推导后的结果。必须保留推导来源；若具体画面由文字模型生成，应保留该模型的完整提示词和输出；若只是 Agent 为还原整理原文，明确属于测试资料准备，不算已验证的文字模型流水线。

这一步验证规则能否用原内容还原风格、布局、图文关系；换内容的复用能力由第7步迁移验证。即使还原很好，也不能说找回了作者原始提示词。

## 交互约定

- 每次集中问1—3个真正影响结果的问题。观察由 Agent 给出，用户纠正；不要把内部分析表变成问卷。
- 第3步原文、页数、角色描述是还原样例。第4步才决定以后运行的契约，不能把样例直接当用户决定。
- 角色只在观察到存在后讨论；没有角色不问。文字设定可提高一致性，身份保真图像是另一种流程，不能混入纯文字还原。
- 正常流程包含第3步；没有执行器、用户选择跳过或未确认生成时，保存方案并标记未实测。不能悄悄省略验证后声称通过。
- 已确认的方案和授权不重复索取；用户明确要求全程自动执行可跳过对应等待，沉默不算同意。
- 约每60秒或阶段变化简报当前步骤、已完成、下一步、影响结果的问题，不要连续跑很久才一次罗列文件。
- 最后说明做到哪步、主入口在哪、用户认可的范围和未验证项。用户无需翻日志才能了解进展。

## 每步页面与历史保留

遵循 [分阶段页面契约](ui-output-contract.md)。第2步独立分析页；第3步与第7步的方案、结果分开；同一阶段修改另存版本。聊天默认给固定index.html入口并说明更新了哪个节点，必要时附阶段深链接和具体问题，源JSON与完整Markdown放次级入口。早期阶段不强制生成三件套；最终交付保持完整。不能把一个flow.html从分析一直覆盖成已验收，再称其代表所有历史阶段。
