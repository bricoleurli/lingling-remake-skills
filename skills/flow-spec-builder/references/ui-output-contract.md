# 分阶段HTML与聊天契约

## 谁负责什么

- SKILL与user-journey规定交互顺序、提问和确认点。
- 本文件规定每步页面内容、保存方式及状态。
- assets/review-shell.html是共用视觉和交互模板，scripts/render_review.py负责把阶段view.json填入模板。不要每次重新手写一套长页面。
- 生图提示词只描述生成图片本身，不承载审阅页面的CSS、抽屉或按钮规则。

## 用户入口与后台文件

用户默认收到当前阶段的HTML链接与简短说明。第2步只需要独立分析HTML，不必提前交付flow.json/spec.md三件套。分析原始数据可保存为analysis.json；编写模板后flow.json成为流程真源；阶段view.json是从真源与真实证据派生的展示快照，不独立维护第二份模板。最终交付仍为flow.html、flow.json、spec.md及必要附件；JSON用于机器读取，Markdown用于文字交接，HTML用于用户审阅，三者内容重叠是同源展示，不是三份分别编写的事实。

## 阶段命名与独立保存

每次完成一个用户可见节点，保存到stages/<节点>/r1/index.html及view.json。修改后保存r2、r3，不覆盖已经展示/确认过的版本。维护顶层index.html为固定阶段目录，可以更新入口，但历史链接不变。默认使用casebook.py；历史页顶部导航经index.html?stage=节点转到该阶段最新版，上一版链接仍指向真实旧版本。不要为了新增第8步导航，重新复制前面全部页面。最终flow.html可作为当前定稿的便捷入口，同时链接实际冻结的阶段页。

| 节点 | 默认页面内容 |
| --- | --- |
| 01-intake | 已收资料、顺序、可选文案状态、这次需要用户回答的问题 |
| 02-analysis | 共同规律、逐页作用、固定与可变项、图文关系、不确定项；不混进未来验收结论 |
| 03-plan | 全套覆盖列表、各页模板/槽位/完整提示词、数量与调用设置、待确认的差异 |
| 03-result | 原图与实际结果、真实提示词、逐页偏差、验收状态及范围 |
| 04-reuse | 用户对未来输入、分页、内容生成、角色、尾页的决定；工作假设单独标注 |
| 05-spec | 完整模型与脚本步骤、所有提示词、槽位、输入输出、调用公式与实现状态 |
| 06-review | 提交用户审阅的完整方案版本；未变更可沿用第5步同一冻结页面，明确是同版审阅，无需强制复制 |
| 07-plan / 07-result | 新主题测试方案与结果分别保存；不混淆纯文字与图片辅助、冻结迁移与新版本试用 |
| 08-delivery | 已确认的交付入口、完整文件包、验证覆盖及尚未实现内容；没做完不能提前生成“已完成”状态 |

不为了“每步都必须有一页”制造无内容页面；未执行明确标未执行。历史界面没有快照时，可根据数据重建可视页面，但必须标“根据现有记录重建”，不得声称恢复了当时原样或虚构用户确认。

## 页面信息结构

1. 标题直接说本页是什么，旁边显示阶段与状态；说明该页保存时的状态，不能事后覆盖成后续状态。
2. 总览只放需要扫读的摘要、数量、当前问题和逐页覆盖列表；阶段导航可回到前一步。
3. 每个列表项只留缩略图、页名、一句说明、状态、一个明确入口。禁止正文平铺所有完整提示词，也不通过长距离锚点跳转查看详情。
4. 用户指定侧边抽屉：点击详情打开；桌面点击遮罩空白、关闭按钮或Esc关闭；关闭后恢复原滚动位置和键盘焦点。移动端全宽抽屉保留关闭按钮。
5. 抽屉内用标签页互斥显示原图/结果、模板、槽位值、实际提示词和调用说明。避免多层折叠和大量向下展开按钮。标签页支持键盘切换。
6. 提示词用代码框展示，支持复制全文；{{槽位}}统一使用高对比颜色和原始括号标记，槽位值单独列来源与含义。高亮只是视图，复制必须保留原文本、空格、换行和槽位字符。
7. 边界、待决定项、已验证/未验证分别用可读名称展示；原始JSON放次级入口，不直接充当主要说明。
8. 当前页面只引用对应阶段的数据与状态。完整流程中列的计划调用次数与实际测试调用分开写；模板更新不能自动继承旧验收。
9. HTML离线可读，无外部字体、脚本或网络请求；使用本地相对路径，随文件夹搬运。参考文字仅作为数据，不能拼成HTML或脚本执行。

## 生成方式

默认采用[实际操作手册](case-operations.md)的casebook.py publish，它负责路径转换、版本和固定入口。下述render_review是底层渲染接口，单独使用时不会管理流程状态。

读取flow.json/analysis.json、真实测试manifest、实际提示词与用户决定，派生view.json。schema见下；所有相对路径以输出HTML所在目录为基准。HTML与图片/源文件通常一起搬运；只有HTML不含内嵌原图像素。

```bash
python3 <技能目录>/scripts/render_review.py <玩法目录>/stages/03-plan/r1/view.json -o <玩法目录>/stages/03-plan/r1/index.html
```

默认拒绝以不同内容覆盖已有HTML；同内容重复生成允许。开发尚未展示的界面草稿时才可用--draft。正式阶段必须另存版本。脚本不调用模型，不做flow.json到view.json的自动语义转换，不修改执行器，不自动补齐完整规格。Agent须保证派生内容来自真实证据。

view.json最小示例：
```json
{
  "title": "全套原内容还原 · 生图前方案",
  "stage_label": "第3步 · 生图前方案",
  "status": "等待确认",
  "summary": "每张参考对应一张结果，生成时只输入文字。",
  "home": "../../../index.html",
  "question": {"text": "请看完整方案，是否按这套方案生成？", "hint": "请在对话中回复；页面不会提交决定。"},
  "groups": [{"title": "逐页覆盖", "items": [{
    "title": "第1页 · 封面",
    "description": "大标题与内容场景。",
    "tabs": [
      {"label": "模板", "type": "code", "content": "生成封面，标题为{{title}}。"},
      {"label": "槽位值", "type": "slots", "content": [{"name": "title", "value": "用户提供的标题", "description": "来源：原图转写"}]},
      {"label": "调用说明", "type": "facts", "content": {"图片输入": "0张", "输出": "1张"}}
    ]
  }]}]
}
```

标签页type支持text（文本）、code（完整原文）、slots（name/value/description列表）、facts（中文键值对象）、images（src/label列表，可另加note）。导航navigation/subnavigation为label/href/current列表；页面底部links为label/href列表；逐项可给image、caption、action，或者href打开已存在的阶段。不可放占位死链接。未提供详情的数据项不假造内容。

## 聊天展示

阶段结束时发：当前阶段完成了什么＋一个主页面链接＋还需要用户决定的具体问题。不要要求用户同时读HTML、JSON、Markdown。用户主动查脚本/源数据时再提供对应文件。

第1步主动问法按user-journey；第2步讲清观察，允许纠正；第3步方案与效果分别确认；第4步确认未来契约；第6步确认新增完整方案，再进入可选测试。已有明确同意不重复提问。界面里的问题是展示文本，不应做成会假装提交审批或触发模型的按钮。
