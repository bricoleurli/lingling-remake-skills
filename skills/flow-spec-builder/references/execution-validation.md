# 执行与验证协议

交互节点先遵循 [用户流程与确认节点](user-journey.md)。本协议规定执行方式，不能用“工具可用/已授权试跑”绕过尚未展示的新方案确认；用户明确要求全程自动执行时遵循其要求。

## 共同连接规则

先按 [模型能力与真实测试](model-access.md) 检查、询问、查文档、配置和记录。账号类型不是能力证据。缺少工具时必须主动提供配置引导，再标明尚未执行；不以交付方案代替已授权且条件齐全的真实测试。

当前flowkit外部执行器只支持一组FLOW_BASE_URL/FLOW_API_KEY；文字与生图模型名分开。若用户两种服务地址不同，须先在案例内实现并测试分服务适配器，不能把两组信息塞进同一变量或声称已支持。该脚本会对无路径URL补/v1；必须先对照供应商文档，必要时修改适配器，不能依赖自动补全猜地址。

## 选择执行器

用户指定工具时遵循用户；未指定且内置生图工具可用时优先使用。调用前读取该工具当前说明及适用的 imagegen 技能，按当前参数和输出规则执行，不猜工具接口。只有使用外部API脚本路径才需要 Base URL、API Key 和 check-api。没有可用工具或接口时，完成分析、规格与提示词，并准确说明生成受阻。

flowkit.py 的 validate/render/plan 可离线使用；run 是外部API路径，不能调用 Codex 内置生图。内置执行由 Agent 编排，不能声称跑通了脚本API。含 text/code 步骤时须按依赖执行并保存真实中间结果；工具无法完成的步骤明确报出，不能跳过后宣称端到端完成。不要把安装、打开预览或 plan 成功当成生成成功。

模型名称以工具实际披露为准。flow.json 中的 models.image 仅用于脚本配置，不能据此推断内置工具型号。遵守已有生成授权，超出授权范围的外部发送或付费操作另行确认；不重复确认同一范围。

## 两种证据不可混用

### 文字规则验证（默认）

原图用于分析和生成后对照。生成时只有最终文字提示词，既不传原图，也不传前一张生成图、风格图或人物图。内置 imagegen 调用省略 referenced_image_paths 和 num_last_images_to_include；其他工具采用等价的零图片输入。提示词中写“纯文字”不能代替检查真实调用参数。

flow.json 的 reference 可保留对照图片；它不是生图授权。检查生成步骤没有图片槽位、图片依赖及 chain/anchor 引用。原图中的字可被转写为 sample_input。需要主体设定时用可替换的 hero 文字输入；只承诺经输出验证的一致程度。

### 用户要求的图片辅助流程

用户明确要求固定角色保真、照片转换或图片输入时，记录每张实际输入及其作用。原始作品分析图、角色资产和上一张生成图分别标注，不把图片辅助效果当作文字规则独立成立的证据。用户已指定纯文字时不得擅自切换图片模式。

## 原内容回填必须可追溯

顺序是抽象模板→原内容输入→展开提示词→生成→对照。模板按页型复用，原主题具体物件与动作必须来自槽位或明示的内容推导规则；逐图重写临摹描述不能计为模板验证。记录模板和输入版本，保存所有实际提示词，避免比较时遗漏额外人工指令。第3步结果不等于第5步后补文字模型链路已实测。

## 冻结与比较

1. 先核对逐页覆盖表：默认每张参考图都有对应还原输出，保持原顺序；只有用户明确选择的部分测试才允许少于参考页数，须记录未覆盖页。再记录模板、实际输入、展开后的逐次提示词、生成设置和版本或哈希。
2. 还原测试通过后冻结模板。迁移只更换约定的内容字段；默认不同时更换 hero 或风格。必须改模板时另立版本，不能把改后结果冒充同模板迁移。
3. 原图与还原结果比较；迁移结果优先与已认可的还原结果比较。保留所有尝试，不隐藏失败或只留最好一张。
4. 检查风格、布局、分页编号、内容到画面的意义、额外文字、原主题残留。把自动检查与人工观察分开；未经逐字校验不声称主文全部准确。
5. 用户认可整体效果后记录认可范围及已知偏差，不无限修饰。单套两轮通过不证明全部主题稳定，更不证明爆款效果。

## 保存与交付

新测试在玩法目录 tests/<测试名>/ 保存 prompts/、原始输出、deliver/、对照HTML及 manifest.json；已有历史证据无需搬移。每次记录实际执行器、已知模型或“未披露”、输入图片清单/数量、提示词路径、输出路径、尺寸、是否重试或编辑、验收状态。原图输入与历史生成图输入都应计入图片数量。

复制工具生成文件到交付目录，保留原文件。不得伪造 flowkit 的 state.json 或 API 成功记录。纯文字实验若有后期排字或修图，另存并披露，保留未改版本。

第3步为默认原内容还原，需按确认节点执行；第7步补测试与迁移按用户选择。用户要求跳过或执行受阻时可交付标注未实测的完整方案，不能伪造验收。最终模板若已变化，旧版本验收只作为历史证据。
