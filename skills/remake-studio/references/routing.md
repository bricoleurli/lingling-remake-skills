# 阶段路由与扩展

| 用户现状/意图 | 执行入口 | 完成依据 |
|---|---|---|
| 有参考图，要拆解 | flow-spec-builder | 按八步交付及真实验证范围 |
| 已有完整拆解，要新建工作台 | remake-workbench-builder | 页面、运行、交付与验收 |
| 有工作台，要添加新玩法 | remake-workbench-builder | 新旧玩法并存、历史保留 |
| 没有生图工具或要换供应商 | 共同model-access规则，再继续当前子技能 | 文档核对、适配、真实测试分别记录 |
| 只问项目当前状态 | 读取本地进度与证据 | 不额外生成或修改 |
| 一次性作图、无关开发 | 不用本总入口 | 使用适用工具 |

总入口不把“读取子技能说明”称作运行成功，也不通过给其他对话发消息模拟技能调用。已有用户授权跨两阶段时直接衔接；只授权第一阶段时交付后停止扩展。

新增子技能需写清触发条件、必要输入、输出文件、下一步接收者、独立使用方式、失败恢复及验证证据。先验证真实任务，再加入路由表；共同模型规则不复制编辑。新增适配器不是新增一个总入口。

项目进度留在用户项目中，建议studio-state.json记录当前阶段、子技能版本、交付路径、用户决定、能力状态引用和待办。未知事实留空；凭据值禁止写入。此文件是执行记录，不是自动工作流引擎。
